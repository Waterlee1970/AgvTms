## 二、后端内核架构分层

### 2.1 四层算法栈

```
┌─────────────────────────────────────────────────────────────┐
│  L4 应用层: HybridScheduler (M1↔M2 统一入口)                │
│  └→ 模式自动切换: Theta*(≤3AGV) / ECBS(>3AGV)              │
│  └→ 弹性降级: Dispatcher→Router→Traffic 任意层崩溃不级联   │
├─────────────────────────────────────────────────────────────┤
│  L3 协同层: MAPF (多Agent路径规划)                          │
│  ├── CBS Solver (Complete-Based Search, 最优解)            │
│  ├── ECBS (Bounding CBS, 次优但快10x)                      │
│  └→ 冲突树搜索 / Cost集中界 / Priority优化                 │
├─────────────────────────────────────────────────────────────┤
│  L2 规划层: Theta* Any-Angle Path Planning                  │
│  └→ LOS(Line-of-Sight) 捷径检测                             │
│  └→ 路径长度比A*缩短20-30%                                  │
│  └→ 支持动态障碍物规避                                      │
├─────────────────────────────────────────────────────────────┤
│  L1 交通管制层: TrafficControlSystem (M1 死锁预防)          │
│  ├── ResourceLockManager (资源锁, 防循环等待)               │
│  ├── 区域容量控制 (Zone Capacity)                           │
│  ├── 拥堵检测与重路由触发                                    │
│  └→ V1算法兼容: ACO+SA+NLP (原型级)                        │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 数据模型领域映射

```
核心实体:
├── Scene (场景)
│   ├── MapGraph { nodes[], edges[] }          # 地图拓扑
│   ├── VehicleType[]                          # 多车型定义
│   └── ConveyorSegment[]                      # 输送线段
│
├── Agent (智能体)
│   ├── AgvState { id, pos, battery, status }  # AGV状态
│   └── AgvAssignment { agv_id, task_id, path } # 调度分配
│
├── Task (任务)
│   ├── AgvTask { pickup, delivery, priority } # AGV任务
│   └── ConveyorTask { type, segments }        # 输送线协同任务
│
├── Schedule (调度结果)
│   ├── SchedulingResult { paths[], metrics }  # V2结果
│   └── DispatchResult { assignments[] }       # V1结果
│
└── Runtime (运行时)
    ├── TrafficControl { locks, congestion }   # 交通管制状态
    └── Simulation { time, events }           # 仿真状态
```

#### 问题4: V1/V2 调度结果结构不一致
**现状**:
```typescript
// api.ts (V1):
interface ScheduleResult {
  assignments: AgvAssignment[];  // [{ agv_id, task_id, path }]
  metrics: ScheduleMetrics;
}

// advancedApi.ts (无V2结果类型!)
// 后端实际返回:
interface SchedulingResult {  // V2
  paths: Dict[str, ScheduledPath];  // { agv_id: { waypoints, cost }}

```

**影响**: 
- DigitalTwin 的 `ThreeDigitalTwin` 接收的数据格式是 V1 的 `assignments`
- 如果切换到 V2 调度，3D可视化会崩溃

**修复方案**:
```typescript
// services/unifiedApi.ts (新建适配层):
export async function runUnifiedSchedule(mode: 'v1' | 'v2' | 'hybrid') {
  if (mode === 'v2' || mode === 'hybrid') {
    const result = await hybridApi.post('/schedule/run', data);
    return transformV2toV1Format(result.data);  // 统一转换
  }
  return api.post('/schedule/run', data);  // V1原样返回
}
```
