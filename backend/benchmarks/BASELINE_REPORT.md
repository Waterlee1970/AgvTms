## 6. 优化建议 (三级优先级)

### P0 — 必须修复 (阻塞达标)

| ID | 问题 | 方案 | 预期效果 | 工作量 |
|----|------|------|----------|--------|
| P0-01 | 单体架构 GIL 限制并发 | Master-Worker 进程拆分 | 吞吐量提升 3-5x | 2周 |
| P0-02 | N+1 数据库查询 (每请求多次DB) | 批量查询 + Redis 缓存层 | P50 降低 50% | 3天 |
| P0-03 | 同步阻塞调用残留 | 全面异步化 audit | P99 降低 40% | 3天 |

### P1 — 应该改善 (提升余量)

| ID | 问题 | 方案 | 预期效果 | 工作量 |
|----|------|------|----------|--------|
| P1-01 | JSON 序列化开销 | 使用 orjson 替代 json | P50 降低 10-20% | 半天 |
| P1-02 | 无 HTTP 连接池 | httpx 异步客户端 + 连接复用 | 连接开销减少 90% | 1天 |
| P1-03 | 日志同步写磁盘 | 异步日志 (loguru/structlog) | I/O等待降低 | 半天 |

### P2 — 可以考虑 (锦上添花)

| ID | 问题 | 方案 | 预期效果 | 工作量 |
|----|------|------|----------|--------|
| P2-01 | 无请求压缩 | gzip/brotli 中间件 | 带宽节省 60-80% | 1天 |
| P2-02 | 缺少响应缓存 | ETag / 条件GET | 304返回减少计算 | 1天 |
| P2-03 | 无限流保护 | slowapi 或自定义限流 | 防止雪崩 | 半天 |
